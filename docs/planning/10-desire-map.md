# 10-desire-map.md
## 바람 지도 (Desire Map)

### 개요
처음 요청에서 최종 정의까지의 변화, 숨은 바람, 기능과의 연결을 정리한다. "왜 이 기능들이 필수인가"의 마지막 답변.

---

## 단계 1: 처음 요청 (Raw Request)

### 원래 문제 정의

```
"숙박 호스트가 새로운 게스트마다 똑같은 안내를 반복해서 하는데,
 이 부분을 줄여줄 수 있는 도구가 필요하다."
```

### 초기 이해

**호스트의 겪는 고통**
- 와이파이 비번 "뭐예요?" → 매번 반복 설명
- 도어락 "안 돼요" → 전화로 설명
- 체크인 "어디서 하나요?" → 매번 맨 앞에 써서 전송

**요청자의 가정**
- "도구"가 있으면 자동화될 것 같다
- "안내서" 형태의 페이지가 필요하다
- 호스트는 "비용을 줄이려고" 할 것이다

**숨은 바람 (불명확함)**
- 호스트 개인: 응대 시간 절약? 밤 편히 자고 싶음?
- 사업: "구매" 모델인가 구독인가?
- 기술: 단순 PDF 공유? SaaS? 링크 공유?

## 단계 2: 다시 정리한 한 줄 문제 (Reframed)

### 재정의 과정

**소크라테스 인터뷰 결과**
```
Q: "안내서 도구가 필요하다는 게, 정확히 뭐가 힘든 거예요?"
A: "밤 10시, 새벽 2시에 계속 메시지가 와요. 자려고 누우면 또 울려요."

Q: "그럼 어떤 형태면 좋을까요?"
A: "그냥 카톡 링크 하나 보내서, 받는 사람이 알아서 보게 할 수 있으면..."

Q: "그런데 왜 기존 앱(Notion, 카톡)을 안 쓰고 새 도구를 원하세요?"
A: "음... 그냥 투박해 보여서. 받는 사람이 '와, 이 숙소는 다르네' 생각하게 
   할 수 있는 예쁜 페이지가 있으면 좋겠어요. 호스트로서도 전문적으로 보이고."

Q: "다른 쓰임새는 없나요?"
A: "청첩장도 같은 방식으로 만들 수 있으면 좋겠어요. 우리 회사원 친구들도 
   모바일 청첩장 고민하는데, 다들 기존 업체는 '평범하다'고 해요."
```

### 재정의된 한 줄

```
"호스트와 예비부부가 '감성 있는 모바일 페이지'를 5분 만에 꾸미고,
 받는 사람이 보기만 해도 '다르다'고 느끼도록, 
 카톡 링크로 공유할 수 있는 모바일 SaaS."
```

### 변화의 핵심

| 항목 | 처음 | 재정의 |
|-----|------|--------|
| 문제 | 반복 응대 시간 낭비 | 감성 + 응대 시간 (동시) |
| 도구 형태 | "도구" (불명확) | 감성 디자인 SaaS |
| 대상 | 호스트만 | 호스트 + 예비부부 2개 버티컬 |
| 핵심 가치 | 기능성 | **감성 + 디자인 + 부드러운 사용감** |
| 수익 모델 | 불명확 | 일회성 구매 ₩29,900 |
| 경쟁 지점 | 기능 풍부도 | **감성·디자인·UX 품질** |

### 왜 달라졌나

```
발견: "사용자는 '기능'이 아니라 '감성'을 1순위로 본다"

호스트 지현:
"도어락 비번을 4자리 큰 글자로 띄우는 페이지면 되는 게 아니라,
 받는 사람이 '오, 이 호스트는 신경 쓰네'라고 느끼도록 
 따뜻하고 예쁜 디자인이 있으면 좋겠어요."

예비부부 수진·민준:
"모바일 청첩장을 만들 때도, 정보를 다 담는 것보다
 받는 사람이 보고 '우와, 감각 있는 커플이네'라고 느껴야 해요."

→ 결론: "완성형 프로덕트로 출시한다. 기능 먼저 추가하지 말고, 
         감성과 디자인의 품질을 끝장을 보자."
```

## 단계 3: 한 줄 정의 (2개 버티컬)

### 버티컬 1: 객실 안내서

```
"새벽 2시 도어락 질문에서 깨지 않도록,
 게스트가 알아서 보는 예쁜 객실 안내서 URL을 5분에 만들어서,
 카톡으로 보내고 싶다."
```

**주체**: 호스트 지현
**상황**: 게스트 예약 당일
**행동**: 5분 안에 도어락·와이파이·체크인 정보 정리
**결과**: 게스트가 링크 클릭 → 예쁜 페이지에서 모든 정보 확인 → 더 이상 질문 없음

### 버티컬 2: 모바일 청첩장

```
"친구들이 받은 카톡 미리보기만 봐도 '우와, 감각 있네'라고 느끼고,
 열어봤을 때 부드러운 모션과 따뜻한 디자인으로 결혼 축하 받으며,
 참석 여부도 쉽게 답하고 싶다."
```

**주체**: 예비부부 수진·민준
**상황**: 결혼식 4주 전
**행동**: 토요일 오후 2시간으로 감성 있는 청첩장 완성
**결과**: SNS에 자랑 → 친구들의 입소문 → "우리 청첩장도 이 앱으로!"

## 단계 4: 바라는 것 정의 (니즈 → 바라는 것)

### 객실 안내서 - 호스트 지현의 바라는 것

**겉으로 말한 것**
- 도어락, 와이파이, 체크인 안내를 한 번에 보낸다
- 반복적인 질문을 받지 않는다

**정말 바라는 것**
- **밤과 근무 시간을 침범받지 않는다** (자유)
- 호스트로서 **전문성 있어 보인다** (신뢰)
- 게스트가 **자동으로 정보를 습득한다** (자동화)
- 호스트의 관심과 배려가 **보인다** (감정 전달)

### 모바일 청첩장 - 예비부부의 바라는 것

**겉으로 말한 것**
- 감성 있는 모바일 청첩장을 만든다
- 5분 안에 완성한다

**정말 바라는 것**
- 결혼이라는 중요한 일을 **감각 있게 대한다** (자존감)
- 받는 사람에게 **좋은 인상**을 남긴다 (평판)
- 결혼 준비 과정이 **즐겁다** (경험)
- 나중에 봐도 **자랑스럽다** (자산)
- 다른 커플과 **구별된다** (개성)

## 단계 5: 바라는 것과 기능의 연결

### 맵: 바라는 것 → 기능 → 사용자 행동

```
┌─────────────────────────────────────────────────────────────┐
│ 정말 바라는 것: "밤 10시에는 핸드폰을 꺼도 된다"               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ 필수 기능:                                                  │
│ 1. [객실 안내서 템플릿]                                     │
│    → 도어락·와이파이·체크인 섹션 필수                     │
│ 2. [URL 발급 + 카톡 공유]                                  │
│    → 게스트가 링크 클릭 → 이제부터 링크로만 응대         │
│ 3. [무제한 수정 + URL 유지]                               │
│    → 다음 게스트는 내용만 수정 (5분)                      │
│ 4. [조회 통계]                                             │
│    → 게스트가 봤다는 확신 (더 이상 "봤어?" 질문 받지 않음)
│                                                             │
│ 사용자 행동:                                               │
│ "새 예약 들어옴 → 5분 안내 작성 → 카톡 URL 전송          │
│  → 다시 자려고 누움 → (더 이상 깨지 않음)"               │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 정말 바라는 것: "SNS에 자랑하고 받는 사람이 감탄한다"          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ 필수 기능:                                                  │
│ 1. [감성 디자인 템플릿]                                     │
│    → "오, 이 청첩장 다르다" 한눈에 느껴지기               │
│ 2. [Toss급 부드러운 모션]                                  │
│    → 받는 사람이 스크롤할 때 "우와, 부드럽네"            │
│ 3. [OG 태그 최적화]                                         │
│    → 카톡 미리보기에서 이미 예쁨                          │
│ 4. [RSVP + 방명록]                                          │
│    → 참석 여부 쉽게 받음                                   │
│    → 축하 메시지 남김 (감정 교환)                         │
│                                                             │
│ 사용자 행동:                                               │
│ "토요일 2시간으로 청첩장 완성 → 카톡 공유 → 친구 반응    │
│  '우와, 예쁜데?' → 인스타 올림 → 다른 친구들 물음        │
│  → 뿌듯해하며 URL 자랑"                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 기능별 바라는 것 맵핑

| 바라는 것 | 필수 기능 | 왜 필수인가 |
|-----|---------|-----------|
| "밤 10시 편하게" | 객실 안내 템플릿 | 호스트가 필요한 섹션만 채울 수 있도록 |
| "밤 10시 편하게" | URL 발급 | 게스트는 링크만 보면 끝 (반복 질문 차단) |
| "밤 10시 편하게" | 무제한 수정 | 다음 게스트는 URL 다시 알려주지 않고 내용만 변경 |
| "밤 10시 편하게" | 조회 통계 | 호스트가 "게스트가 봤다"는 확신 (더 이상 불안) |
| "5분 제작" | 에디터 (간단함) | 필드 최소화, 좌우 분할 레이아웃 |
| "5분 제작" | 자동 임시저장 | 네트워크 끊겨도 로컬에 저장 → 재시도 |
| "감성 느껴지기" | 감성 디자인 시스템 | Noto Serif KR, 따뜻한 색상, 여백 |
| "감성 느껴지기" | Toss급 모션 | 부드러운 spring 애니메이션 (60fps) |
| "SNS 자랑" | OG 태그 | 카톡 미리보기에서 이미 예쁨 |
| "SNS 자랑" | 방명록 | 친구들의 축하 메시지 (기억) |
| "SNS 자랑" | RSVP | 참석 여부 쉽게 받음 (관리 간단) |
| "다시 쓸래" | URL 유지 | 공유된 링크가 계속 작동 (자산) |

## 단계 6: 이번 버전에서 뺄 것 & 이유

### 뺄 것 리스트

| 기능 | 왜 뺐나 | 대신 하는 것 |
|-----|--------|-----------|
| **예약 연동** (에어비앤비 자동 연결) | "완성형" 우선 → 자동화는 나중 | 호스트가 수동으로 카톡 공유 (5분) |
| **블록 조립** (섹션 자유 추가/조합) | 5분 제작을 방해 | 템플릿은 고정된 섹션 구조 (커스텀: on-off만) |
| **호스트 대시보드** (통계, RSVP 관리) | MVP 범위 초과 | 마이페이지에서 기본 통계만 (조회 수) |
| **다국어 자동 번역** | 첫 출시는 한국 시장만 | 영어는 손수정으로 충분 |
| **구독 모델** | "일회성 구매"가 사용자 심리에 맞음 | 1년 유지 후 연장 선택 |
| **소셜 로그인 강제** | 에디터는 비로그인 가능해야 | 결제 시점에만 가입 요구 |
| **고급 이미지 편집** | 복잡함 + 시간 낭비 | 클라이언트 리사이즈로 충분 |

### 뺀 이유의 핵심

```
"얇은 MVP가 아니라 완성형 프로덕트로 출시한다"

= 모든 기능에서 "감성·속도·품질"을 우선한다
= 기능 수를 줄이고 각 기능의 완성도를 높인다
= 호스트와 예비부부 2명을 완벽히 만족시킨다
= 나중에 추가하는 기능은 "더하기"가 아니라 "고도화"다
```

### 언제 추가할 것

| 기능 | 추가 시점 | 신호 |
|-----|---------|------|
| 예약 연동 | Phase 2 | 사용자가 "자동으로 못 할까?" 요청 반복 |
| 블록 조립 | Phase 3 | 호스트가 "내 섹션을 추가하고 싶어" 요청 |
| 다국어 | Phase 2 | 외국인 게스트 비율 > 20% |
| 호스트 대시보드 | Phase 2 | 사용자 > 100명 + RSVP 관리 필요 |
| 구독 모델 | 검토 필요 | 일회 모델이 포화되었을 때 |

## 단계 7: 바라는 것과 성공의 연결

### 성공 = 바라는 것이 현실이 된 것

```
호스트 지현의 바라는 것:
"밤 10시 자려고 누우면, 폰은 꺼도 된다"

Roomy가 제공하는 경험:
1. 예약 들어옴 → 5분에 안내서 완성
2. 카톡으로 URL 공유
3. 게스트는 링크에서 모든 정보 확인
4. 밤 10시 → 핸드폰 끔 → 숙면
5. 새벽 2시 → 도어락 질문 없음 → 계속 숙면

성공의 증거:
"호스트 지현이 마이페이지 통계에서 '게스트가 조회했다'는 걸 확인하고,
 안심하며 핸드폰을 내려놓고 잠든다"

---

예비부부 수진·민준의 바라는 것:
"친구들이 우리 청첩장을 보고 '우와, 감각 있네'라고 말한다"

Roomy가 제공하는 경험:
1. 토요일 오후 2시간으로 완성
2. 부드러운 모션, 따뜻한 디자인 (Toss급)
3. 카톡 미리보기에서 이미 예쁨
4. 친구들의 반응: "이거 뭐? 다시 만들고 싶은데?"
5. SNS에 올림 → 더 많은 반응
6. 10월 결혼식 → 받는 사람도 "감각 있네" 평가

성공의 증거:
"수진이가 마이페이지에서 "조회: 234명"을 보고,
 민준이에게 "봤어? 234명이 우리 청첩장을 봤대"라고 자랑한다"
```

## 최종 검증 체크리스트

### 모든 기능이 바라는 것을 충족하는가?

- [ ] **템플릿 갤러리**: 호스트/예비부부가 "이거다" 찾음 (5분 안에)
- [ ] **에디터**: 호스트가 도어락·와이파이 입력 (3분), 예비부부가 이름·사진 (5분) 완료
- [ ] **실시간 미리보기**: 호스트/예비부부가 우측에서 결과를 즉시 확인 (만족감)
- [ ] **결제**: 비로그인 → 결제 시점에 가입 (진입장벽 낮춤)
- [ ] **URL 발급**: 카톡 공유 링크가 예쁜 미리보기로 뜸 (자랑하고 싶음)
- [ ] **뷰어 모션**: 게스트가 "우와, 부드럽다" 느낌 (감성)
- [ ] **방명록/RSVP**: 호스트/예비부부가 참석 여부/축하 메시지 받음 (소통)
